# MCP 2026-07-28 Migration Review

Status: applied for the initial public release.

## Upstream Changes

MCP `2026-07-28` removes protocol sessions and the initialization handshake,
adds `server/discover`, requires `resultType` on results, and introduces
multi-round-trip requests for client input. The official Python SDK 2.0 serves
this revision and all earlier revisions from the same server.

Python SDK 2.0 also renames the high-level `FastMCP` class to `MCPServer`; the
decorator APIs for tools and prompts remain available.

## Impact on This Project

| Upstream change | Project action |
| --- | --- |
| `FastMCP` removed | Migrated imports, construction, and type annotations to `MCPServer`. |
| SDK 1.x maintenance-only | Pinned `mcp>=2.0.0,<3`. |
| Per-result server identity | Added the package version to `MCPServer`. |
| Stateless protocol core | No redesign needed: `CarlaSession` already exists only inside one script execution. |
| Modern discovery and `resultType` | Delegated to SDK 2.0 and covered by an in-memory client test. |
| MRTR and subscriptions | Not used by the current one-tool stdio server. |
| Sync handlers use worker threads | Compatible with the tool's blocking subprocess boundary. |

## Verification

The test suite connects an SDK 2.0 `Client` directly to the server, negotiates
`2026-07-28`, checks server identity, calls `execute_carla_script`, and validates
its structured result. Existing sandbox and application tests remain unchanged.
